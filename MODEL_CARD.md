#### Description

`ibm-nasa-geospatial/Prithvi-EO-2.0-300M-BurnScars` at revision `a3f2c410e45b8ac7417976614528a872f024d831` is the upstream authors' burn-scar-mapping fine-tune of Prithvi-EO-2.0 (Szwarcman et al., 2024), NASA and IBM's foundation model for Harmonized Landsat Sentinel-2 imagery: a ViT-L masked autoencoder (24 blocks, embedding dimension 1024, 16 × 16 patches, six input bands) pretrained on 4.2 M global multispectral samples, here in the variant without temporal and location embeddings. The checkpoint packaged here, `Prithvi_EO_V2_300M_BurnScars.pt` (1,297,798,380 bytes, SHA-256 `0c5f9334…`), is the `terratorch` `EncoderDecoderFactory` model that fine-tuning produced — the encoder (294 tensors), a `SelectIndices` → `ReshapeTokensToImage` → `LearnedInterpolateToPyramidal` neck over encoder depths 5, 11, 17 and 23 (11 tensors), a U-Net decoder with 512 / 256 / 128 / 64 channels (48 tensors) and a two-class head (2 tensors): 324,204,674 parameters in float32, trained with cross-entropy and AdamW (learning rate 10⁻⁴, `ReduceLROnPlateau`) on the 804 labelled 512 × 512 HLS scenes of the HLS Burn Scars dataset (blue, green, red, narrow NIR, SWIR 1 and SWIR 2; 2018–2021, contiguous United States) for 40 epochs (2,665 steps) on the authors' non-overlapping splits, with the run of lowest validation loss selected from five. At inference the model standardises the six bands with the training configuration's statistics, encodes the scene, builds a feature pyramid from four depths, decodes it and returns two logits per pixel at input resolution; `argmax` gives the mask.

What this repository adds is the `PrithviBurnScarPipeline` class in `src/prithvi_burnscar_segmentation_pipeline/pipeline.py`: manifest verification of the 10-file Hub snapshot before any model library is imported (`verify_snapshot`, which also checks the converted file against its pinned digest when present), fresh-clone staging at the pinned revision (`stage_missing_files`), a **static audit of the pickle** that lists every global it would import with `pickletools` and refuses anything outside the allow-list (`audit_pickle`, digest pinned), a **one-time conversion** through torch's weights-only unpickler into a strictly loaded model whose state dict is saved as safetensors (`convert_model`), model construction from the installed `terratorch` package with `backbone_pretrained=False` (`build_model`), scene validation with named ceilings (`validate_inputs`, `validate_dataset`), segmentation with softmax scores and class fractions (`predict`), pixel-pooled IoU / F1 / precision / recall against the not-burned baseline (`evaluate`), bounded fine-tuning of the neck, decoder and head — optionally also the last encoder block — with frozen BatchNorm statistics (`adapt`), and a safetensors adapter artifact that is digest-verified and scope-checked before deserialization (`save_artifact`, `from_artifact`). `samples.py` pins the dataset tarball and its 88 members, extracts exactly those members without `extractall`, assigns the model repository's split roles, and reads/writes GeoTIFF pairs for BYOD with `tifffile` (no rasterio, no georeferencing); `metrics.py` holds the confusion-matrix metrics and the baseline.

Two things about this row are stated rather than hidden. **The model already trained on the tutorial's dataset** — the 44 scenes are drawn from the same splits the checkpoint was fine-tuned and selected on — so the frozen numbers are in-distribution and the bounded adaptation has little to learn from 24 scenes; the card reports the paired held-out numbers as observations and claims no improvement. **Georeferencing and dates are not used**: scenes are read as pixel arrays, the encoder variant carries no temporal or location embedding, and scenes larger than a chip are not tiled.

#### Intended Use and Limitations

###### Primary Intended Uses

Two tasks are exposed. **Burn-scar segmentation:** input is a 512 × 512 scene of six surface-reflectance bands (blue, green, red, narrow NIR, SWIR 1, SWIR 2; values in [0, 1] or × 10 000, no-data 0 or −9999) or a GeoTIFF from which they are read (13-band Sentinel-2 L1C files are reduced to the six HLS-equivalent bands); output is a per-pixel mask (0 = not burned, 1 = burn scar), the two softmax scores per pixel and the burn fraction. **Adaptation to labelled scenes:** given at least four scenes with masks (0 / 1 / −1 for no data), the pipeline fine-tunes the neck, decoder and head (optionally also the last encoder block) with a small learning rate and validation-loss epoch selection, predicts with the adapted model and exports the changed tensors as an 81 MB adapter. Envisioned application domains are burned-area mapping from optical satellite scenes in research and public-sector workflows — post-fire extent mapping, building training data for a regional model, teaching and evaluating foundation-model fine-tuning for Earth observation; and prototyping a segmentation service whose skill is then measured against the operator's own labels. In a larger system the pipeline is a single-scene segmenter and an adaptation baseline whose masks feed an analyst's review or a downstream tiling/mosaicking step; it is not a burn-severity product, an active-fire detector or a change-detection system.

###### Primary Intended Users

Intended users are Earth-observation scientists, wildfire and land-management analysts, and machine-learning engineers who work with HLS or Sentinel-2 scenes, in research, public service or the DIMER model workbench. The pipeline assumes its users understand that the model learned six specific bands at a specific scaling and that band order and reflectance units are part of the contract; that a burned-area label carries its own uncertainty at scar edges, under smoke and over mixed vegetation; that neighbouring scenes of one fire are near-duplicates, so splits must be by fire or tile; that the not-burned baseline is the number to read first on scenes with little burn; and that a 12-scene evaluation is a sanity check, not a measurement of skill.

###### Out-of-scope use cases

1. **Capability boundary:** the pipeline segments burn scars in single-date six-band optical scenes and fine-tunes the decoder side of the model. It does not estimate burn severity or dNBR, detect active fires, use temporal stacks, tile scenes, mask clouds or smoke, or correct atmosphere; and it does not reproduce the published benchmark scores.
2. **Input boundary:** scenes are exactly 512 × 512 pixels with exactly six bands in the HLS order; values must be finite reflectance in [−0.5, 2] after scaling (values above 1 are divided by 10 000); labels hold only 0, 1 and −1; datasets hold 4..2,000 records with at least one burn-scar pixel. Other sizes, band sets, radiometric products (digital numbers, radiance), or label vocabularies are not inputs.
3. **Decision boundary:** not for autonomous action on a mask — evacuation, insurance or damage assessment, timber salvage, land-use decisions — without verification against the deployment's own reference over a representative set of scenes and an analyst's review. A mask from this pipeline is an experiment output, not a burned-area product.
4. **Provenance boundary:** not for settings that require the upstream serialized checkpoint to be executed as-is, or that forbid any one-time unpickling of a third-party checkpoint even through a restricted loader after a static audit; the trust boundary is documented under *Mitigations* and in `docs/WEIGHTS.md`.

#### Factors

###### Groups

The pipeline's inputs are satellite reflectance scenes, not records about people, so age, gender, skin type and socioeconomic status are not attributes of any input and no demographic evaluation applies. The relevant groups are geographic and physical: fires differ by ecosystem (grassland, shrubland, conifer forest, agricultural land), by burn severity and age (fresh scars read differently from regrowth), by terrain and shadow, and by the HLS tile and year — the dataset covers the contiguous United States in 2018–2021 only. Upstream reports one pooled score per split; this repository measures 12 test scenes and 8 validation scenes, pooled over pixels, and reports no per-tile numbers — whose fires are mapped well is therefore unmeasured here, and a deployment serving a region or a biome should measure it there. Communities in landscapes under-represented in the training scenes, or whose surfaces resemble burn spectrally (dark soils, wet fields, shadowed slopes), bear the error.

###### Instrumentation

The instruments are Landsat 8's OLI and Sentinel-2's MSI as harmonised by HLS: surface reflectance at 30 m in HLS S30 tiles, stored as float32 reflectance in the dataset's scenes with 0 as no-data, six of the harmonised bands taken (B02, B03, B04, B8A, B11, B12). The labels were derived by the dataset authors from burned-area products and quality-checked, with −1 marking no-data. Instrument and processing defects reach the model as feature error — a different atmospheric correction, cloud or smoke residue, terrain shadow, or a band-order mistake all shift the six values the model reads, and the pipeline detects none of them: validation checks shapes and ranges, not radiometry. The model's own instrument is its patching, 16 × 16 pixels per token, so a 480 m square is one token and narrow fire lines are sub-token.

###### Environment

Operating environment: Python 3.12 with `torch==2.14.0`, `torchvision==0.29.0`, `terratorch==1.2.13` (which brings torchgeo, lightning, timm, segmentation-models-pytorch, albumentations, rasterio and others as its own dependencies; the pipeline imports only `terratorch.models.EncoderDecoderFactory`), `tifffile==2026.9.15`, `numpy==2.5.3`, `safetensors==0.8.0`, `huggingface-hub==1.32.0` (`pyproject.toml`). The model is float32 as shipped and runs in float16 autocast on CUDA (`device` defaults to CUDA when visible, CPU otherwise); the recorded run is under *Runtime* (load 22 s, 12 scenes scored in 1.5 s, a 48-step adaptation in 9.4 s, 2.1 GB of GPU memory on an RTX 5070 Ti laptop GPU). CPU execution works but is slow (tens of seconds per scene). Data environment: the model assumes HLS-like surface reflectance of the six bands at the training configuration's statistics, single-date scenes of fires similar to the dataset's; it degrades, without any error, on other sensors, other radiometric products, other continents and seasons, and on dark soils, wet fields or shadow, all of which can read as burn.

#### Metrics

###### Performance Measures

The pipeline reports, exactly as `metrics.segmentation_metrics` names them, over the pooled labelled pixels of every scene scored (pixels labelled −1 excluded): `iou` per class (`not burned`, `burn scar`), `mean_iou`, `accuracy`, and for the positive class `precision`, `recall` and `f1`, plus the confusion matrix, the labelled-pixel count and the positive fraction. Three comparison points are read together: the **not-burned baseline** (`majority_baseline`, every pixel predicted as unburned — its accuracy equals the unburned fraction and its burn IoU is 0), the **frozen model**, and the **adapted model**. IoU and F1 of the burn-scar class are the headline because accuracy is dominated by unburned land; precision and recall are kept apart because adaptation traded one for the other on this sample (recall 0.970 → 0.950, precision 0.953 → 0.974 on the test scenes). Every number in this repository is sample-sanity evidence on 12 test and 8 validation scenes from one seeded run with no dispersion estimate; the upstream test IoU of 87.5 on the full split is not reproduced or claimed — the 12 scenes here were filtered to contain burn and score higher.

###### Decision thresholds

The default decision rule is an `argmax` over the two per-pixel logits, equivalent to a 0.5 threshold on the burn-scar softmax score; `predict` returns both scores so a deployment can apply its own threshold, and the pipeline sets none. The limits fixed during development are input-contract limits, not decision thresholds — the 512 × 512 scene size, the six-band count, the reflectance range after scaling, the label vocabulary, the 4..2,000 record range — chosen so that a rejection names a real defect and an acceptance never means "radiometrically correct". An operator who needs a threshold (a minimum burn score before a pixel counts as burned, or a minimum burned fraction before a scene is flagged) must set it from verification against their own labels, weighing the cost of a missed burned pixel against a false one, and own it. `adapt` selects the epoch with the lowest validation loss, which is the only selection this repository performs.

###### Approaches to uncertainty and variability

Reported metrics come from one seeded run on **pixel-pooled** held-out scenes — 12 test scenes from the model repository's test split for the numbers, 8 validation scenes for epoch selection only — with no cross-validation, bootstrap, ensemble or repeated-run averaging, and no dispersion is reported: with 12 scenes of one dataset, any interval would be dominated by which scenes were drawn, and large burns dominate the pooled counts. A caller who needs one evaluates many scenes across fires and years and reports per-scene distributions, and owns that design. Sources of run-to-run variability: the flip augmentation and shuffling are seeded (`numpy` generator), initialisation is the pinned checkpoint, and BatchNorm statistics are frozen; float16 autocast, non-deterministic GPU kernels and the gradient scaler are not controlled, so a re-run can differ in the last decimals of the adapted numbers while the frozen numbers are reproducible. The softmax scores are the model's outputs and are **not calibrated probabilities**; no per-pixel uncertainty beyond them is produced, and calibration against the operator's labels is theirs to do.

###### Mitigations

1. **Supply-chain integrity:** `MODEL_ID` and the 40-hex `MODEL_REVISION` are module constants; `verify_snapshot()` checks `modelId`, `revision`, and the byte size and SHA-256 of all 10 manifest entries before any load, additionally asserts the checkpoint's digest against the package constant, and raises on the first mismatch (tests flip bytes, change the identity and delete a file and assert each raises). `stage_missing_files()` fetches only manifest-listed files absent on disk, only at `MODEL_REVISION`, only when `allow_download=True`, and refuses a manifest naming another model. `.gitattributes` carries `weights/** -text`.
2. **Executable serialization handled explicitly (asset spec §11.2):** the pickle is not loaded by the runtime path. `audit_pickle` lists every global it would import with `pickletools` (`collections.OrderedDict`, `torch._utils._rebuild_tensor_v2`, `torch.FloatStorage`, `torch.LongStorage`) and refuses anything else; the audit digest is pinned. `convert_model` runs size → digest → audit before `torch.load(weights_only=True)` (torch's restricted unpickler, which cannot construct arbitrary objects), requires a `state_dict` of tensors whose every key carries the Lightning `model.` prefix, and loads it with `strict=True` into `EncoderDecoderFactory().build_model(...)` with `backbone_pretrained=False`; the model's state dict is re-saved as safetensors. Tests craft an archive with `os.system` and a plain pickle of a `complex` and assert each is refused before anything is unpickled.
3. **Deterministic, digest-pinned serving file:** `verify_converted` checks size and SHA-256 against `CONVERTED_SHA256` / `CONVERTED_BYTES` (reproduced by the build, the smoke run and the executed notebook); the model loads with `strict=True` and a parameter-count check. With `require_source=False` (the DIMER-hosted case) the converted file alone is accepted, still digest-verified.
4. **Data integrity and archive safety:** the dataset tarball is pinned by byte size and SHA-256 (`fetch_tarball` hashes it before any member is read and refuses a mismatch); each of the 88 pinned members is pinned again by size and SHA-256 in `SAMPLE_RECORDS`; `extract_pinned_members` streams the archive once, copies out only pinned members through `extractfile`, writes each under its base name in the cache (never at a path from the archive; no `extractall`, no symlinks, no directories), refuses a member digest mismatch, and refuses an archive that lacks a pinned member. Roles come from the model repository's split files; `check_split_disjoint` refuses a scene present in two splits.
5. **Artifact integrity and scope:** the adapter is safetensors, not a pickle. `load_artifact` validates the manifest **before** deserialising anything: the artifact format and `format_version`, the recorded base model id, revision and converted-base digest, exactly one weights entry named `adapter.safetensors` that resolves inside the artifact directory, an `adapter.trainable` that is exactly `decoder` or `decoder+last_block`, and a tensor list equal to the exact set that scope may change on this model; the safetensors keys must then equal that set and every shape must match. The weights file's SHA-256 is checked against the adjacent manifest — it detects corruption or drift of the file relative to that manifest, not authenticity: an actor who can replace both files can make them agree.
6. **Input integrity:** `predict`, `evaluate`, `adapt`, `validate_inputs` and `validate_dataset` route through one checker, so their acceptance criteria cannot diverge; it rejects missing keys, wrong shapes, band counts and scene sizes, non-finite values, out-of-range reflectance after scaling, label values outside {−1, 0, 1}, duplicate ids and datasets without a burn-scar pixel; no-data is replaced by 0 as upstream does and values above 1 are scaled by 10⁻⁴, both reported.
7. **Training discipline:** only the declared scope receives gradients (the encoder stores no graph), BatchNorm running statistics stay frozen (batches of two scenes would corrupt them), the learning rate defaults to 10⁻⁵, gradients are clipped at norm 1, the epoch is selected by validation loss with the frozen model as epoch 0, and `adapt` is transactional — any failure restores the pre-adaptation tensors, re-freezes the model and clears the adapter.
8. **Import boundary:** verification, the static audit and validation run before `torch`, `terratorch`, `timm`, `lightning`, `safetensors` or `huggingface_hub` are imported (fleet RTM-001); `tests/test_import_boundary.py` fails if a rejected request reaches a model library, and an AST check fails if any of them is imported at module level.
9. **Honest scope:** validation is labelled structural, the sample is labelled in-distribution, the softmax scores are labelled uncalibrated, the baseline is printed before any model number, the notebook asserts only what the procedure guarantees, and no upstream benchmark is claimed.

Not implemented, and therefore not claimed: no tiling of larger scenes, no cloud or smoke masking, no burn-severity estimation, no full-encoder fine-tuning, no calibration, no per-tile evaluation, and no measurement beyond the 44-scene sample.

###### Risks and harms

1. **A conversion can be subtly wrong:** the evidence is the strict key-and-shape match against the rebuilt architecture and sane predictions on the upstream example scenes, under one `terratorch` version. A future package version that changed a block's semantics while keeping its parameter names would load strictly and silently compute something else; the exact pin is the control.
2. **A pickle audit is an allow-list, not a proof:** the static audit bounds what the unpickler can name; torch's weights-only unpickler bounds what it can construct. The digest pins tie the audited bytes to the loaded bytes, and the unpickle happens once, in the operator's environment.
3. **Spectral confusion:** dark soils, wet fields, shadowed slopes, harvested cropland and old scars can read as fresh burn and are predicted with the same silent confidence; the operator bears the false alarms and the data subject — communities on the map — bears the misses.
4. **In-distribution optimism:** the sample scenes come from the dataset the model trained on; a reader who carries the frozen numbers to a new region, biome or sensor draws an unsupported conclusion.
5. **Near-duplicate leakage:** neighbouring scenes of one fire are near-duplicates; a split over shuffled scenes makes memorisation look like skill. Neither the model nor this repository can detect a leaking split the operator builds.
6. **Catastrophic forgetting and drift:** fine-tuning the decoder on a few scenes of one fire can degrade other fires; validation selection guards against the worst case on the validation scenes only.
7. **Band-order and unit mistakes:** a scene with the bands in another order or in radiance units is segmented without complaint; validation catches shapes and ranges, not meaning.
8. **Automation bias and proprietary data:** a clean-looking mask invites acting on it without review, and the realistic confidentiality failure is licensed imagery or an unreleased assessment uploaded to a cloud notebook — inference is local, but the runtime may not be the operator's.

###### Use cases

The model must not be used to direct evacuation, aid, insurance, damage assessment, salvage or land-use decisions, or to produce any map presented as an operational burned-area product, without verification against the deployment's own labels over a representative set of scenes and a qualified analyst's review; it must not be used as evidence about Prithvi-EO-2.0's benchmark skill, which this repository does not measure; it must not be used to load or execute the upstream pickle in any way other than the audited, digest-verified, one-time conversion this repository performs; it must not be used to redistribute HLS Burn Scars scenes without the CC BY 4.0 attribution; and it must not be used in any way that breaches the Apache-2.0 terms of the upstream weights or the DIMER deployment terms.

## Input/output contract

- `PrithviBurnScarPipeline.from_pretrained(device=None, weights_dir=None, allow_download=False, require_source=True, report=None)`: stages and verifies the snapshot, audits and converts the checkpoint when the safetensors file is absent (reporting through `report`), builds the architecture from `terratorch` and loads the safetensors strictly. `require_source=False` accepts the digest-verified converted file without the checkpoint.
- `predict(records, *, batch_size=4) -> dict` with `model` (id, revision, key, `adapted`), `classes`, `decision_rule`, `predictions` (per record: `id`, `mask` (H, W) uint8, `scores` (2, H, W) float32, `class_fraction`), `seconds`.
- `evaluate(records, *, batch_size=4) -> dict`: `n_records`, `metric`, `model` (`iou` per class, `mean_iou`, `accuracy`, `precision`, `recall`, `f1`, `confusion`, `labelled_pixels`, `positive_fraction`), `baseline_not_burned` (the same fields), `adapted`, `seconds`.
- `adapt(train, val=None, *, epochs=4, lr=1e-5, batch_size=2, trainable="decoder", seed=0, progress=None) -> dict`: bounded AdamW fine-tuning; returns the trainable set and counts, hyperparameters, `best_epoch`, per-epoch `history` (epoch 0 = the frozen model, each with `train_loss`, `val_loss` and the validation metrics) and `seconds`. `trainable="decoder+last_block"` also unfreezes encoder block 23.
- `save_artifact(output_dir, metadata=None) -> Path` writes `adapter.safetensors` (the trained tensors) + `manifest.json` (format, base model id/revision/key and converted digest, adaptation record, history, tensor names, file size and SHA-256); `from_artifact(...)` / `load_artifact(...)` verify all of that before deserialising.
- `validate_inputs(record) -> dict` (`id`, `shape`, `reflectance_range`, `has_label`, `label_fraction`, `ignored_pixels`) and `validate_dataset(records, *, min_records=4, max_records=2000, require_labels=True) -> dict` (normalised `records`, counts, `class_pixel_fraction`, `ignored_pixels`, `reflectance_range`, `digest`) raise exactly what the execution path would raise; `check_record` returns one normalised record. `read_chip(path, band_indices=None)` / `read_mask(path)` read GeoTIFFs with `tifffile`; `fetch_sample_dataset(cache_dir=None)` / `fetch_corpus` / `fetch_tarball` / `extract_pinned_members` are the pinned-data primitives; `load_byod_dataset(path)`, `write_sample_pair`, `write_dataset_csv` the BYOD I/O; `split_dataset`, `check_split_disjoint`, `dataset_manifest` the split helpers; `segmentation_metrics`, `confusion_matrix`, `metrics_from_confusion`, `majority_baseline` the metrics.
- `audit_pickle(path, allowed=…)`, `convert_model(path=None)`, `verify_converted(path=None)` and `build_model()` are the serialization primitives.
- Constants: `BANDS` (6), `S2_L1C_BAND_INDICES = (1, 2, 3, 8, 11, 12)`, `MEANS`, `STDS`, `CONSTANT_SCALE = 1e-4` (applied only above 1), `IMAGE_SIZE = 512`, `NUM_CLASSES = 2`, `CLASS_NAMES = ("not burned", "burn scar")`, `IGNORE_INDEX = -1`, `MIN_RECORDS = 4`, `MAX_RECORDS = 2000`, `PARAMETER_COUNT = 324204674`, `STATE_TENSORS = 355`, `ADAPTATION_MODES = ("decoder", "decoder+last_block")`, `ARTIFACT_FORMAT = "org.valcorza.prithvi-burnscar-segmentation.adapter.v1"`, `TAR_SHA256`, `DATASET_REVISION`.

| Field | Status |
|---|---|
| **DIMER status** | **Planned / conditional** — the `.pt` asset-format and deserialization-trust review the fleet inventory requires is what this repository implements; the review's acceptance is Kurt's call |
| Licence | Apache-2.0 (weights, the upstream Prithvi-EO-2.0 code, TerraTorch, and this repository's code) — use, modification, redistribution and commercial use permitted with the licence and notices preserved |
| Weights | Would be redistributed converted, not unmodified: the served artifact is the deterministic safetensors derived from the pinned checkpoint, with both identities recorded (asset spec §11.2); this repository redistributes neither |
| Remote code | **Not required** — no Hub-hosted module is imported; the model class comes from `terratorch==1.2.13` on PyPI |
| Executable serialization | One pickle, unpickled **once** at conversion through torch's weights-only loader after a digest check and a static audit; a DIMER profile should carry the safetensors file and never the `.pt` |
| Runtime | `terratorch==1.2.13` + `torch==2.14.0` + `torchvision` + `tifffile`; float16 autocast on CUDA; a GPU is advisable (a scene takes tens of seconds on CPU); the `terratorch` install is heavy (torchgeo, lightning, rasterio and their dependencies) |
| Upload format | `prithvi-eo-2.0-300m-burnscars.safetensors` (1,297,682,024 bytes, SHA-256 `4209c5a0…`); **the `.pt` file must not be uploaded** |
| Input contract | 512 × 512 scenes of six bands (blue, green, red, narrow NIR, SWIR 1, SWIR 2) as arrays or GeoTIFFs; surface reflectance in [0, 1] or × 10 000; labels 0 / 1 / −1 for adaptation |
| Sample data | the HLS Burn Scars tarball (CC BY 4.0) fetched at run time from the Hub at an immutable revision, 88 pinned members extracted, never vendored |

**One thing is open, and it is neither the licence nor the code:** whether a one-time unpickle through torch's weights-only loader, after a static audit with a pinned digest — in the build and in the tutorial runtime, where the notebook converts what it downloads — meets the DIMER bar, or whether DIMER should host only the safetensors converted and verified once by the maintainer. The served artifact is the same file either way.
